# 爱知·名古屋 2026 赛程与赛果

本地网站从官方 `Schedules & Results` 接口同步网球、棒球、板球、排球、乒乓球、羽毛球和手球的逐场赛程与赛果。所有时间转换为 UTC+8（北京时间）。

服务运行后访问：`http://127.0.0.1:4173`

后台只在每天北京时间 08:00（含）至 23:00（不含）自动同步，08:00 同步完整赛程，比赛日约每 5 秒读取实时比分。自动重试、小分及积分/对阵刷新也遵守此时段，夜间只读现有数据；手动“立即同步”、展开比赛或切换积分/对阵视图仍可读取官网。错过的全量同步会在下一个允许时段补一次，官网实际限流的重试期限保持有效。网页关闭时后台仍会运行。

点击比赛行或比分按钮可展开官网分局、分盘等小分。各项目有“赛程赛果”“小组积分”“淘汰赛对阵图”三个视图，可以按男单、女双等类别切换。详情和当前积分/对阵视图会自动刷新。官网没有公布的数据明确显示未公布；本地不会虚构小分、积分或晋级关系。比分速度受官网更新频率影响，不是逐球推送。

团体赛详情可按“第1场、第2场……”切换子比赛，显示单／双打类别、完整选手名单、状态、单场比分和各局小分。尚未开赛的子比赛保留已公布名单，不把预设的 0 分当成赛果。展开详情约每 5 秒刷新，进行中的小分缓存为 4 秒，多人查看共享缓存；刷新保留当前查看的子比赛。

布局可切换列表、2列、3列、4列或5列。卡片按从左到右、从上到下排列，进行中的比赛优先，继续支持日期、状态和类别筛选。列数偏好保存在当前浏览器；手机自动收敛为单列，平板最多两列。

已安装 macOS 登录后台服务 `com.lizhenjie.aichi-schedule`。电脑需要开机、登录并联网；睡眠或关机时不会同步，唤醒/重新登录后在允许时段补同步。全量同步失败后 5 分钟重试；比分更新失败后逐步延长重试至最多 5 分钟，429 限流等待 1 小时；若期限落在夜间则顺延至 08:00。保留最近成功数据，前端通过数据版本自动刷新，即使后台页面错过同步过程也能更新。

阶段依据官方日程说明及各项目阶段代码核实。网球的 `R32-` 虽在官网描述为 “Second Round”，本地准确显示“32强赛”。棒球超级循环赛和女子手球循环赛保持各自规则，详见 `STAGE_VERIFICATION.md`。

手动启动：

```bash
python3 server.py --host 127.0.0.1 --port 4173
```

验证（在网站目录）：

```bash
PYTHONPATH=. python3 -m unittest discover -s tests -v
node --test tests/test_frontend.cjs
node --test tests/test_submatches.cjs
```

前端验证需要 Playwright 与本机 Google Chrome；运行网站本身只需 Python 3.12 和标准库。

## 共享比分来源

由一个服务统一采集官网数据，其他实例通过 `SCHEDULE_UPSTREAM_URL` 共享其赛程、比分、小分、积分及对阵图，避免重复采集。例如：

```bash
SCHEDULE_UPSTREAM_URL=https://two026asiagames-abc-oregon.onrender.com python3 server.py --host 0.0.0.0 --port 4173
```

也可用 `--upstream` 参数覆盖环境变量。配置后不启动本地采集线程；立即同步按钮转交给上游。负责采集的 Oregon 服务不设置该变量。网页和 `/api/health` 仍由当前实例提供，保活任务应同时覆盖采集实例。

仅转发固定来源的必要接口，保留上游状态码、数据时间戳与旧数据标记；上游不可用时明确返回错误，不把旧比分当作实时比分。
